Variant paths#

variant_get, try_variant_get, variant_delete, and the : operator use a path to select a value inside a Variant. Paths follow the Spark 4.2 syntax, a small subset of JSONPath.

The examples on this page use this table:

CREATE TABLE requests AS
SELECT parse_json('{"service":"api","user":{"id":7,"roles":["admin","dev"]},"http.status":200,"user-agent":"curl"}') AS request;

Syntax#

A path starts with $, which selects the whole value, followed by any number of steps:

Step

Selects

.name

The field name. The name ends at the next . or [.

['name'] or ["name"]

The field name, which can contain any character except the quote around it.

[n]

The array element at index n, starting from 0.

 
SELECT variant_get(request, '$.user.id', 'INT') AS id,
       variant_get(request, '$.user.roles[1]', 'VARCHAR') AS second_role,
       variant_get(request, '$["http.status"]', 'INT') AS status
FROM requests;

+----+-------------+--------+
| id | second_role | status |
+----+-------------+--------+
| 7  | dev         | 200    |
+----+-------------+--------+

Field names are case-sensitive, and $.* selects a field named *, not every field. A path that does not match the value, such as a missing field, an index past the end of an array, or a field step on an array, returns SQL NULL.

The path is a string expression, so it can also come from a column. A SQL NULL path returns SQL NULL.

A path that does not start with $, such as user.id or an empty string, is invalid. Paths have no wildcards, slices, filters, negative indexes, or recursive descent (..). An invalid path raises an error, even in try_variant_get.

variant_delete also rejects $ alone, because it deletes a field or an array element.

Field names with special characters#

Use a quoted step for a field name that contains . or [. $.http.status selects the field status inside an object http, while $["http.status"] selects the field named http.status:

SELECT variant_get(request, '$.http.status') IS NULL AS nested_missing,
       variant_get(request, '$["http.status"]', 'INT') AS status
FROM requests;

+----------------+--------+
| nested_missing | status |
+----------------+--------+
| true           | 200    |
+----------------+--------+

Every character between the quotes is part of the name, including ], $, and \. To select a name that contains ', quote it with ", and the reverse.

The : operator#

value:path is shorthand for variant_get with $. in front of the path, or $ when the path starts with [. So request:user.roles[0] reads $.user.roles[0], and request:['http.status'] reads $['http.status']:

SELECT request:user.roles[0]::VARCHAR AS first_role,
       request:['http.status']::INT AS status,
       request:['user-agent']::VARCHAR AS agent
FROM requests;

+------------+--------+-------+
| first_role | status | agent |
+------------+--------+-------+
| admin      | 200    | curl  |
+------------+--------+-------+

Quote a field name that is not a plain SQL identifier, such as user-agent. Without quotes, request:user-agent subtracts a column named agent from request:user.

Backtick-quoted names, such as request:`user-agent`, return SQL NULL, while Spark selects the field. Use request:['user-agent'] instead. Support is tracked in #141.
