Variant paths#

variant_get, try_variant_get, variant_delete, and the : operator use a path to select a value inside a Variant. Paths follow the Spark 4.2 syntax, a small subset of JSONPath.

The examples on this page use this table:

CREATE TABLE requests AS
SELECT parse_json('{"service":"api","user":{"id":7,"roles":["admin","dev"]},"http.status":200,"user-agent":"curl"}') AS request;

Syntax#

A path starts with $, which selects the whole value, followed by any number of steps:

Step

Selects

.name

The field name. The name ends at the next . or [.

['name'] or ["name"]

The field name, which can contain any character except the quote around it.

[n]

The array element at index n, starting from 0.

 
SELECT variant_get(request, '$.user.id', 'INT') AS id,
       variant_get(request, '$.user.roles[1]', 'VARCHAR') AS second_role,
       variant_get(request, '$["http.status"]', 'INT') AS status
FROM requests;

+----+-------------+--------+
| id | second_role | status |
+----+-------------+--------+
| 7  | dev         | 200    |
+----+-------------+--------+

Field names are case-sensitive. A path that does not match the value, such as a missing field, an index past the end of an array, or a field step on an array, returns SQL NULL.

Paths have no wildcards, slices, filters, negative indexes, or recursive descent (..). $.* selects a field named *. An invalid path raises an error, even in try_variant_get.

The path is a string expression, so it can also come from a column.

Field names with special characters#

Use a quoted step for a field name that contains . or [. $.http.status selects the field status inside an object http, while $["http.status"] selects the field named http.status:

SELECT variant_get(request, '$.http.status') IS NULL AS nested_missing,
       variant_get(request, '$["http.status"]', 'INT') AS status
FROM requests;

+----------------+--------+
| nested_missing | status |
+----------------+--------+
| true           | 200    |
+----------------+--------+

Every character between the quotes is part of the name, including ], $, and \. To select a name that contains ', quote it with ", and the reverse.

The : operator#

value:path is shorthand for variant_get(value, 'path'), where path is a rootless path, written without the leading $:

SELECT request:user.roles[0]::VARCHAR AS first_role,
       request:['http.status']::INT AS status,
       request:['user-agent']::VARCHAR AS agent
FROM requests;

+------------+--------+-------+
| first_role | status | agent |
+------------+--------+-------+
| admin      | 200    | curl  |
+------------+--------+-------+

Quote a field name that is not a plain SQL identifier, such as user-agent. Without quotes, request:user-agent subtracts a column named agent from request:user.

Backtick-quoted names, such as request:`user-agent`, return SQL NULL instead of the field. Use request:['user-agent']. Support is tracked in #141.

Deleting with variant_delete#

variant_delete only accepts paths that start with $, and the path must select a field or array element, not $ itself.

Rootless paths#

variant_get and try_variant_get also accept paths without the leading $, and the : operator always uses them:

With $

Without $

$

'' (empty string)

$.user.roles[0]

user.roles[0]

$["http.status"]

["http.status"]

They differ from $ paths in two ways:

  • A path that starts with $ is always a $ path, so '$type' is an invalid path, not the field $type. Use '$.$type' or '["$type"]'.

  • Inside brackets, \ escapes the next character, so '["a\\b"]' selects the field a\b and '["a\b"]' selects the field ab.

Unifying the two forms is tracked in #166.

Differences from Spark#

  • Spark only accepts $ paths in function arguments.

  • A SQL NULL path, such as a NULL in a path column, selects the whole value. Spark returns SQL NULL.

  • After :, Spark decodes backtick-quoted names and keeps \ as part of quoted names.
