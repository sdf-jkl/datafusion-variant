Variant paths#

variant_get, try_variant_get, variant_delete, and the : operator use a path to select a value inside a Variant. Paths follow the Spark 4.2 syntax, a small subset of JSONPath.

The examples on this page use this table:

CREATE TABLE requests AS
SELECT parse_json('{
  "service": "api",
  "user": {
    "id": 7,
    "roles": ["admin", "dev"]
  },
  "http.status": 200,
  "user-agent": "curl"
}') AS request;

Syntax#

A path starts with $, which selects the whole value, followed by any number of steps:

Step

Selects

.name

The field name. The name ends at the next . or [.

['name'] or ["name"]

The field name, which can contain any character except the quote around it.

[n]

The array element at index n, starting from 0.

 
SELECT variant_get(request, '$.user.id', 'INT') AS id,
       variant_get(request, '$.user.roles[1]', 'VARCHAR') AS second_role,
       variant_get(request, '$["http.status"]', 'INT') AS status,
       variant_get(request, '$.http.status', 'INT') AS nested_status
FROM requests;

+----+-------------+--------+---------------+
| id | second_role | status | nested_status |
+----+-------------+--------+---------------+
| 7  | dev         | 200    | NULL          |
+----+-------------+--------+---------------+

$.http.status looks for a field status inside an object http, so quote a name that contains . or [. Unlike JSONPath, \ inside quotes is not an escape character, so $["a\b"] selects the field a\b. Field names are case-sensitive.

Paths have no wildcards, slices, filters, negative indexes, or recursive descent (..), and $.* selects a field named *.

NULLs and errors#

  • A path that does not match the value, such as a missing field, an index past the end of an array, or a field step on an array, returns SQL NULL.

  • The path can be any string expression, such as a column. A SQL NULL path returns SQL NULL.

  • A path that does not start with $, such as user.id or an empty string, is invalid. An invalid path raises an error, even in try_variant_get.

  • variant_delete also rejects $ alone, because it deletes a field or an array element.

The : operator#

value:path is shorthand for variant_get with $. in front of the path, or $ when the path starts with [. So request:user.roles[0] reads $.user.roles[0], and request:['http.status'] reads $['http.status']:

SELECT request:user.roles[0]::VARCHAR AS first_role,
       request:['http.status']::INT AS status,
       request:['user-agent']::VARCHAR AS agent
FROM requests;

+------------+--------+-------+
| first_role | status | agent |
+------------+--------+-------+
| admin      | 200    | curl  |
+------------+--------+-------+

Chaining : reads the same path, so request:user:roles[0] returns the same value as request:user.roles[0]. These forms do not work as expected:
